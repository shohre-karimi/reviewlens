## پوشش تست (coverage)

پوشش یعنی چند درصد خط‌های کد حداقل یک بار در تست‌ها اجرا شده‌اند (`make coverage`).

- اول **۹۶٪** بود. مهم‌ترین بخش پوشش‌داده‌نشده، تبدیل خطاهای Anthropic SDK بود (کلید نامعتبر،
  محدودیت درخواست، قطع اتصال و ...). این همان قسمتی است که قول می‌دهد کاربر پیام فارسی ببیند، نه
  stack trace؛ پس تست برایش لازم بود.
- برای این کار، تست‌ها **همان exceptionهای واقعی SDK** را می‌سازند (با یک پاسخ HTTP ساختگی،
  مثلاً ۴۰۱) و بررسی می‌کنند که هر کدام به نوع خطای درست تبدیل شود. این کار برای هر دو SDK
  (Anthropic و OpenAI) و بدون شبکه انجام می‌شود.
- حالا: **۹۸٪** و **۲۵۵ تست**.
- فایل‌های صفحه‌های اپ در درصد حساب نمی‌شوند. Streamlit آن‌ها را مثل اسکریپت اجرا می‌کند و
  coverage نمی‌تواند خط‌هایشان را دنبال کند، ولی هر سه صفحه با ۱۰ تست `AppTest` تست شده‌اند.

**نکته:** پوشش ۱۰۰٪ هدف نیست. پوشش فقط می‌گوید یک خط *اجرا* شده، نه این‌که *درست* بررسی شده.
مهم این است که بخش‌های حساس (اعتبارسنجی، خطاها، نشت داده، حلقه‌ی agent) تست واقعی داشته باشند.

## مرور نهایی در برابر «Definition of done»

| معیار در `CLAUDE.md` | وضعیت |
|---|---|
| `make install && make test && make lint` | ✅ همان دستورها مستقیم اجرا شدند: نصب، ۲۵۵ تست، ruff، mypy. خود برنامه‌ی `make` روی این سیستم نصب نیست (`winget install ezwinports.make`) |
| `reviewlens run-experiments` نتایج را از روی تنظیمات تکرار کند | ✅ روی سیستم دوم اجرا شد و همان جدول را داد (یک خانه ۰٫۰۰۱ تفاوت) |
| `reviewlens agent local-test` بدون کلید API | ✅ ۱۲/۱۲ |
| `reviewlens agent eval` جدولش را بنویسد | ⚠️ با کلاینت ساختگی تست شده؛ **با مدل واقعی اجرا نشده** (Ollama نصب نیست) |
| `make app` اپ را اجرا کند | ✅ اپ اجرا و هر سه صفحه در مرورگر بررسی شد (با `python -m streamlit run`، همان دستور `make app`) |
| README: نصب، حالت‌های اجرا و یافته‌ها | ✅ |
| pre-commit | ✅ هر ۹ hook روی کل پروژه رد شدند (با venv فعال) |

## چک‌لیست قبل از ارائه

1. نصب Ollama و یک مدل با tool calling: `ollama pull qwen2.5:7b`
2. اجرای ارزیابی واقعی:
   ```powershell
   $env:OPENAI_MODEL = "qwen2.5:7b"
   reviewlens -e configs/agent/ollama.yaml agent eval
   ```
   نتیجه در `docs/agent_tests.md` نوشته می‌شود. معیار موفقیت در برگه‌ی طراحی: دقت انتخاب ابزار
   دست‌کم ۸۰٪.
3. یک بار تست چت روی لپ‌تاپ، هم در CLI (`agent chat`) و هم در صفحه‌ی گفتگوی اپ.
4. روی هر سیستم تازه، اول: `data download`، `data prepare`، `run-experiments`، `evaluate`، و
   `train -m logistic_regression -f 1.0 --save`
5. بخش «نقش هوش مصنوعی» در `docs/report_outline.md` را خودم کامل کنم.

## مفاهیم کلیدی

- **Coverage:** درصد خط‌هایی که تست‌ها اجرا کرده‌اند. ابزاری برای پیدا کردن قسمت‌های تست‌نشده
  است، نه نمره‌ی کیفیت.
- **Definition of done:** فهرست شرط‌هایی که از اول پروژه تعیین شده تا معلوم باشد کار کِی تمام است.
  گزارش صادقانه یعنی موردی که انجام نشده (ارزیابی واقعی agent) به‌صراحت گفته شود.
