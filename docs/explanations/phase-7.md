# فاز ۷: اپ Streamlit

## چه چیزی ساخته شد؟

| فایل | کار |
|---|---|
| `app/streamlit_app.py` | نقطه‌ی شروع: تنظیم صفحه، استایل راست‌به‌چپ، منوی سه صفحه (`st.navigation`) |
| `app/common.py` | بخش‌های مشترک: خواندن تنظیمات، ابزارهای cache‌شده، CSS راست‌به‌چپ، نام فارسی برچسب‌ها |
| `app/app_pages/analyze.py` | صفحه‌ی ۱: تحلیل یک نظر (بدون مدل زبانی) |
| `app/app_pages/results.py` | صفحه‌ی ۲: پاسخ سؤال پژوهش، جدول macro-F1، نمودار اصلی |
| `app/app_pages/agent_chat.py` | صفحه‌ی ۳: گفتگو با دستیار و ردپای ابزارهای هر پاسخ |
| `Makefile` | `make app` |
| `tests/test_app.py` | ۱۰ تست برای هر سه صفحه با `AppTest` خود Streamlit، بدون مرورگر |

اجرا:
```
make app                                     # حالت پیش‌فرض (Anthropic)
# حالت Ollama (PowerShell):
$env:OPENAI_MODEL="qwen2.5:7b"; $env:REVIEWLENS_EXPERIMENT="configs/agent/ollama.yaml"; make app
```

## تصمیم‌های طراحی

### ۱. اپ هیچ منطق جدیدی ندارد
هر سه صفحه فقط از کدهای فازهای قبل استفاده می‌کنند:
- «تحلیل نظر» همان ابزار `analyze_review` را از راه `run_tool` صدا می‌زند. پس پیش‌بینی و
  اعتبارسنجی ورودی در اپ، CLI و agent **دقیقاً یکی** است.
- «نتایج» همان توابع `report` و `plots` فاز ۵ را روی `runs.csv` اجرا می‌کند.
- «گفتگو» همان `run_agent` فاز ۶ است.

اگر باگی در منطق باشد، یک جا درست می‌شود و همه‌جا اثر می‌کند.

### ۲. هر صفحه یک فایل
سه صفحه در `app_pages/` جدا هستند و `streamlit_app.py` فقط منو را می‌سازد. هر فایل کوتاه و
مستقل است: برای تغییر یک صفحه فقط همان فایل را باز می‌کنیم. `AppTest` هم می‌تواند مستقیم به
هر صفحه برود (`switch_page`).

### ۳. حالت اجرا با متغیر محیطی
اپ همان فایل‌های YAML را می‌خواند که CLI می‌خواند:
- `REVIEWLENS_CONFIG`: تنظیمات اصلی (پیش‌فرض `configs/default.yaml`)
- `REVIEWLENS_EXPERIMENT`: فایل اضافه، مثلاً `configs/agent/ollama.yaml`

برای عوض کردن حالت اجرا، کد عوض نمی‌شود. تست‌ها هم از همین راه، اپ را به تنظیمات موقت وصل می‌کنند.

### ۴. cache: مدل و داده فقط یک بار بارگذاری می‌شوند
Streamlit با هر کلیک کل اسکریپت صفحه را دوباره اجرا می‌کند. بدون cache، مدل و ۶۹ هزار نظر هر بار
از دیسک خوانده می‌شدند.
- `st.cache_resource` برای `ReviewTools`: یک نمونه برای هر ترکیب تنظیمات.
- `st.cache_data` برای CSV نتایج. **زمان آخرین تغییر فایل** جزو کلید cache است؛ اگر آزمایش‌ها
  دوباره اجرا شوند، نتیجه‌ی جدید خودکار نمایش داده می‌شود.

### ۵. راست‌به‌چپ (RTL)
Streamlit حالت RTL ندارد، پس با کمی CSS:
- کل صفحه و منوی کناری `direction: rtl`؛
- Streamlit روی متن‌ها `text-align: left` می‌گذارد که جدا override شد (این مشکل فقط در مرورگر دیده شد؛
  پایین‌تر توضیح داده شده)؛
- کد، JSON، جدول‌ها و نمودارها **چپ‌به‌راست** می‌مانند، چون محتوایشان انگلیسی یا عدد است.

### ۶. پاسخ سؤال پژوهش از داده ساخته می‌شود، نه دستی
جمله‌ی بالای صفحه‌ی نتایج را تابع `research_answer` از جدول مقایسه‌ی جفت‌شده می‌سازد. یک روش
نیمه‌نظارتی فقط وقتی «بهتر» حساب می‌شود که هم میانگینش بالاتر باشد و هم در **همه‌ی** seedها
برنده شده باشد. اگر آزمایش‌ها با داده یا تنظیمات دیگری اجرا شوند، جمله هم خودکار عوض می‌شود.

### ۷. صفحه‌ی گفتگو در حالت «بدون مدل»
| وضعیت | رفتار صفحه |
|---|---|
| تنظیمات ناقص (مثلاً `OPENAI_MODEL` نیست) | هشدار و راهنمای سه حالت اجرا؛ گفتگو نمایش داده نمی‌شود |
| Anthropic بدون کلید در متغیرهای محیطی | از همان اول پیام و «راهنمای راه‌اندازی». گفتگو فعال می‌ماند، چون SDK می‌تواند از پروفایل ورود (`ant auth login`) هم کلید بگیرد |
| خطای سرویس هنگام گفتگو | پیام فارسی **با رنگ قرمز** در جای پاسخ |

### ۸. ردپای ابزارها
زیر هر پاسخ دستیار یک بخش بازشونده‌ی «ردپای ابزارها (n فراخوانی)» هست: گام، نام ابزار، ورودی
(JSON) و خروجی، و خطاها با ⚠️. این همان trace حلقه‌ی agent است و نشان می‌دهد پاسخ از کدام
داده آمده؛ یعنی agent چیزی از خودش نساخته است.

## بررسی در مرورگر واقعی

علاوه بر تست‌ها، اپ واقعاً اجرا شد و هر سه صفحه در مرورگر دیده و از آن‌ها عکس گرفته شد. سه مشکل
فقط در مرورگر پیدا شد و هیچ تستی آن‌ها را نمی‌گرفت:
1. متن پیام‌های گفتگو و فهرست‌ها چپ‌چین بود؛ با یک قاعده‌ی CSS درست شد.
2. خطای «کلید ندارید» مثل یک پاسخ عادی دیده می‌شد؛ حالا قرمز است.
3. بدون کلید، کاربر تا اولین پیام نمی‌فهمید که گفتگو کار نمی‌کند. علتش این است که SDK
   Anthropic کلید را فقط موقع ارسال درخواست بررسی می‌کند. حالا از همان اول اطلاع داده می‌شود.

**بررسی‌نشده:** گفتگو با یک مدل واقعی (Ollama هنوز نصب نیست). قبل از ارائه، یک بار روی لپ‌تاپ
با Ollama تست شود.

## مفاهیم کلیدی

- **مدل اجرای Streamlit:** با هر تعامل کاربر، کل اسکریپت صفحه از بالا دوباره اجرا می‌شود.
  `st.session_state` چیزهایی را نگه می‌دارد که باید بین اجراها بمانند (تاریخچه‌ی گفتگو).
- **`cache_resource` و `cache_data`:** اولی برای اشیای سنگین مشترک (مدل)، دومی برای داده‌ای که
  کپی‌اش برگردانده می‌شود (جدول نتایج).
- **AppTest:** اجرای اسکریپت Streamlit در خود پایتون، بدون مرورگر: می‌توان متن نوشت، دکمه زد و
  خروجی را بررسی کرد.
